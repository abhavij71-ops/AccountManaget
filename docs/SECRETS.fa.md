# Secretها (اطلاعات محرمانه)

Account Manager به چند مقدار محرمانه نیاز دارد — یک Token مشترک برای Cron،
یک کلید رمزنگاری، رمز عبور پنل مدیریت پلتفرم، و شناسه Merchant درگاه
پرداخت. هیچ‌کدام از این‌ها هرگز داخل کد منبع نوشته نمی‌شوند. هرکدام از
طریق یک تابع واحد خوانده می‌شوند، `loadSecret()` (`includes/secrets.php`):

۱. ابتدا یک Environment Variable با همان نام.
۲. اگر آن تنظیم نشده باشد (یا خالی باشد) — حالت رایج در هاست اشتراکی، جایی
   که اغلب اصلاً نمی‌توانید Environment Variable تنظیم کنید — یک فایل ساده
   PHP به نام `account-manager-secrets.php`، که **یک پوشه بالاتر** از پوشه
   خود برنامه نگه‌داری می‌شود.

فقط لازم است برای هر Secret یکی از این دو روش را انتخاب کنید؛ بیشتر
کاربران هاست اشتراکی از فایل برای همه‌چیز استفاده خواهند کرد.

## فایل را کجا قرار دهیم

اگر برنامه مثلاً در این مسیر Deploy شده باشد:

```
/home/youruser/public_html/          <- خود برنامه (فایل‌های این Repository)
```

فایل Secrets باید اینجا قرار بگیرد:

```
/home/youruser/account-manager-secrets.php
```

— یک سطح بالاتر از پوشه خود برنامه، **خارج** از هر چیزی که یک وب‌سرور
بتواند برای Serve مستقیم پیکربندی شود. این عمدی است: حتی یک پیکربندی
اشتباه در وب‌سرور که باعث شود فایل‌های `.php` به‌صورت متن ساده از داخل
پوشه برنامه Serve شوند، هرگز نمی‌تواند این فایل را افشا کند، چون اصلاً
داخل آن پوشه نیست.

در هاست اشتراکی معمولی (مثل cPanel)، `public_html/` (یا هر چیزی که Document
Root شما تنظیم شده) دقیقاً همان پوشه خود برنامه است — پس فایل Secrets درست
کنار آن، یک سطح بالاتر قرار می‌گیرد؛ هرگز داخل `public_html/`.

## نمونه فایل

فایل `account-manager-secrets.php` را دقیقاً با این ساختار بسازید:

```php
<?php
return [
    'CRON_TOKEN' => 'یک-مقدار-تصادفی-طولانی-اینجا',
    'ADMIN_PASSWORD' => 'یک-رمز-عبور-قوی-اینجا',
    'ZARINPAL_MERCHANT_ID' => 'شناسه-مرچنت-زرین‌پال-شما',
    'MAIL_ENCRYPTION_KEY' => 'یک-مقدار-تصادفی-طولانی-اینجا',
];
```

فقط کلیدهایی را که واقعاً نیاز دارید پر کنید. کلیدی که موجود نباشد (یا
به‌صورت رشته خالی رها شود) به‌عنوان «پیکربندی‌نشده» در نظر گرفته می‌شود: به
ترتیب، درخواست‌های Cron رد می‌شوند، هرگز نمی‌توان وارد پنل مدیریت شد،
پرداخت‌های زرین‌پال نمی‌توانند شروع شوند، یا رمز SMTP/SMS نمی‌تواند ذخیره
شود. داشبورد مدیریت هم یک بنر هشدار نشان می‌دهد که کدام‌یک از این‌ها
(به‌جز `ADMIN_PASSWORD`، که برای ورود به همان داشبورد از قبل به آن نیاز
داشته‌اید) هنوز خالی هستند.

## نحوه تولید هر مقدار

| کلید | برای چه کاری است | چگونه تولید شود |
|---|---|---|
| `CRON_TOKEN` | مجوز اجرای `cron.php` را وقتی از طریق HTTP فراخوانی می‌شود می‌دهد — قابلیت «Cron از طریق URL» هاستینگ، یا `curl` از یک Crontab سیستمی. وقتی `php cron.php` را از یک ترمینال واقعی اجرا می‌کنید اصلاً لازم نیست. | یک مقدار تصادفی: `php -r "echo bin2hex(random_bytes(32));"` (یا `openssl rand -hex 32`). |
| `ADMIN_PASSWORD` | تنها رمز عبور مشترک برای پنل اپراتور پلتفرم در `/admin/` — کاملاً جدا از ورود هر Tenant. | یک رمز عبور قوی و یکتا — تولیدکننده رمز عبور مدیر رمزهای شما، یا `openssl rand -base64 24`. |
| `ZARINPAL_MERCHANT_ID` | حساب Merchant شما را به درگاه پرداخت زرین‌پال (`billing.php`) معرفی می‌کند. | تولید نمی‌شود — آن را از داشبورد Merchant زرین‌پال خود کپی کنید. |
| `MAIL_ENCRYPTION_KEY` | رمز عبور SMTP و API Key سرویس‌دهنده SMS را پیش از ذخیره در دیتابیس رمزنگاری می‌کند. | یک مقدار تصادفی: `openssl rand -hex 32`. تغییر آن پس از اینکه یک رمز/کلید قبلاً ذخیره شده، آن مقدار ذخیره‌شده را غیرقابل‌رمزگشایی می‌کند — پس از تغییر، آن را دوباره وارد و ذخیره کنید. |

## بررسی درستی کار

با `ADMIN_PASSWORD` وارد `/admin/` شوید — داشبورد دربارهٔ هرکدام از سه
مورد دیگر که هنوز خالی باشند هشدار می‌دهد. `CRON_TOKEN` و
`MAIL_ENCRYPTION_KEY` بلافاصله اهمیت دارند (بدون آن‌ها، ایمیل خروجی
نمی‌تواند ارسال شود و `cron.php` هر درخواست HTTP را رد می‌کند)؛
`ZARINPAL_MERCHANT_ID` فقط زمانی اهمیت پیدا می‌کند که واقعاً بخواهید
پرداخت بپذیرید.
