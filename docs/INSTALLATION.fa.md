# راهنمای نصب

🇬🇧 [Installation in English](INSTALLATION.md)

## پیش‌نیازها

- PHP نسخه **۸.۰ یا بالاتر** با افزونه‌های `pdo_sqlite` و `mbstring` فعال (هر دو در تقریباً همه هاست‌های اشتراکی و نصب‌های پیش‌فرض PHP موجود هستند)
- هر وب‌سروری که بتواند PHP را اجرا کند و به `.htaccess` احترام بگذارد (معمولاً Apache با `mod_rewrite`/`mod_authz_core` در هاست اشتراکی؛ برای Nginx به نکته پایین مراجعه کنید)
- دسترسی نوشتن برای پردازه PHP روی پوشه `data/`
- بدون نیاز به Node.js، بدون Composer، بدون دسترسی SSH

## ۱. قرار دادن فایل‌ها روی سرور

کل پروژه (همه فایل‌ها و پوشه‌ها) را در ریشه وب‌سایت خود آپلود کنید، یا در یک زیرپوشه اگر می‌خواهید برنامه در آدرسی مثل `https://yourdomain.com/accounts/` قرار بگیرد. برنامه از هر دو مکان به‌درستی کار می‌کند — آدرس پایه خودش را به‌صورت خودکار تشخیص می‌دهد.

برای تست لوکال، سرور داخلی PHP کافی است:

```bash
cd accountmanager
php -S localhost:8000
```

## ۲. اجرای نصب‌کننده

فایل `install.php` را در مرورگر باز کنید، مثلاً `https://yourdomain.com/install.php`.

- در اولین بازدید، دیتابیس SQLite و همه جدول‌ها به‌صورت خودکار ساخته می‌شوند.
- سپس از شما خواسته می‌شود حساب مدیر را بسازید: نام کاربری، نام کامل (اختیاری) و رمز عبور (حداقل ۸ کاراکتر).
- در صورت موفقیت، صفحه تأیید همراه با لینک ورود نمایش داده می‌شود.

اگر بعد از ساخته‌شدن حساب مدیر دوباره `install.php` را باز کنید، فقط پیام «سیستم قبلاً نصب شده است» را می‌بینید — این فایل **هرگز** اطلاعات یا حساب مدیر شما را بازنویسی نمی‌کند.

## ۳. حذف `install.php`

پس از اتمام نصب، فایل `install.php` را از سرور حذف کنید (یا حداقل به خارج از ریشه وب منتقل کنید). باقی ماندن آن خطر از دست رفتن داده ندارد — چون به سیستم نصب‌شده دست نمی‌زند — اما یک مسیر غیرضروری است که بهتر است حذف شود.

```bash
rm install.php
```

## ۴. اطمینان از محافظت پوشه `data/`

پوشه `data/` فایل `database.sqlite`، یعنی کل دیتابیس شما، را نگه می‌دارد. این پوشه از قبل شامل موارد زیر است:

- `data/.htaccess` — دسترسی مستقیم وب را کاملاً مسدود می‌کند (سازگار با هر دو نحو Apache 2.2 و 2.4)
- `data/index.php` — یک لایه محافظتی دوم که حتی اگر `.htaccess` به هر دلیلی نادیده گرفته شود، کد ۴۰۳ برمی‌گرداند

پس از نصب، این موضوع را خودتان بررسی کنید: باز کردن مستقیم آدرس `https://yourdomain.com/data/database.sqlite` در مرورگر **باید** خطای 403 Forbidden بدهد، نه خود فایل. اگر این‌طور نبود، ممکن است هاست شما تنظیم `AllowOverride None` داشته باشد — با پشتیبانی هاست تماس بگیرید یا پوشه `data/` را به بالای ریشه وب منتقل کرده و مقدار `DATA_DIR` در `config.php` را متناسب با آن تغییر دهید.

### اگر از Nginx به‌جای Apache استفاده می‌کنید

فایل `.htaccess` روی Nginx اثری ندارد. به‌جای آن این بلوک را به تنظیمات سرور خود اضافه کنید:

```nginx
location /data/ {
    deny all;
    return 403;
}
```

## ۵. ورود

به `login.php` (یا فقط ریشه سایت — به‌صورت خودکار هدایت می‌شوید) بروید و با حساب مدیری که ساختید وارد شوید.

## به‌روزرسانی

این پروژه ابزار Migration دیتابیس ندارد. برای اضافه‌کردن فیلدهای نسخه‌های آینده، باید دستورات `ALTER TABLE` مربوطه را خودتان روی `data/database.sqlite` اجرا کنید، یا نصب را از نو انجام دهید. همیشه قبل از دست‌زدن به schema، از `data/database.sqlite` نسخه پشتیبان تهیه کنید.

## پشتیبان‌گیری

کل وضعیت برنامه در یک فایل قرار دارد: `data/database.sqlite`. فقط همین یک فایل را با هر زمان‌بندی که می‌خواهید پشتیبان بگیرید (یک cron ساده که آن را از سرور کپی کند کافی است).

## عیب‌یابی

| نشانه | علت احتمالی |
|---|---|
| صفحه سفید خالی | نمایش خطای PHP به‌طور پیش‌فرض خاموش است (`display_errors=0` در `config.php`)؛ لاگ خطای PHP هاست خود را بررسی کنید |
| «خطا در اتصال به دیتابیس» | پردازه PHP نمی‌تواند در `data/` بنویسد — مجوزهای پوشه را بررسی کنید (معمولاً 0755 کافی است) |
| ورود همیشه ناموفق است | رمز عبور به بزرگی/کوچکی حروف حساس است؛ اگر مطمئنید درست است، دوباره `install.php` را باز کنید تا پیام «قبلاً نصب شده» را ببینید (یعنی دیتابیس سالم است)، سپس تنظیمات Session سرور را بررسی کنید |
| CSS/فونت‌ها بارگذاری نمی‌شوند | برنامه پس از نصب به مسیر دیگری منتقل شده است؛ `config.php` آدرس پایه را از `DOCUMENT_ROOT` استخراج می‌کند — به محاسبه `APP_BASE_URL` در `config.php` مراجعه کنید |
