# راهنمای چندزبانه‌سازی — Account Manager

🇬🇧 [Read in English](I18N.md)

وضعیت فعلی: **فارسی (پیش‌فرض) + انگلیسی**، حدود ۵۹۰ کلید ترجمه، پوشش تقریباً کامل رابط کاربری.
این سند توضیح می‌دهد سیستم چطور کار می‌کند، چه کارهایی باقی مانده، و برای افزودن زبان سوم (مثلاً عربی) دقیقاً چه باید کرد.

---

## ۱. معماری فعلی

```
includes/lang.php   → تابع t()، ثابت SUPPORTED_LANGUAGES، جهت متن
lang/fa.php         → آرایه key => value فارسی
lang/en.php         → آرایه key => value انگلیسی
set-language.php    → تغییر زبان + redirect امن به همان صفحه
```

انتخاب زبان در `$_SESSION['lang']` نگه داشته می‌شود. تابع `t()` سه سطح fallback دارد: زبان فعلی ← زبان پیش‌فرض ← خود کلید.

**قرارداد نام‌گذاری کلیدها:** `<حوزه>.<نام>` — مثلاً `nav.emails`, `common.save`, `accounts.view_card_number`, `enum.Active`, `history.Account Created`.

**جهت متن** از خود فایل ترجمه می‌آید، نه از کد:
```php
'app.direction' => 'rtl',   // در fa.php
'app.direction' => 'ltr',   // در en.php
```
این الگوی درستی است و باید حفظ شود.

## ۲. کارهای باقی‌مانده برای چندزبانه‌سازی

فهرست به‌ترتیب اولویت. موارد ۱ تا ۵ پیش از افزودن زبان سوم باید انجام شوند.

### اولویت بالا — بدهی ساختاری

**۱. تقارن فایل‌های زبان را برقرار کنید.**
فایل `lang/en.php` دارای ۳۴ کلید `enum.*` و ۲۲ کلید `history.*` است که در `lang/fa.php` **وجود ندارند**. در فارسی، تابع `enumLabel()` به نگاشت‌های hardcode شده در `includes/helpers.php` برمی‌گردد. این کار می‌کند اما نامتقارن است — و برای زبان سوم فوراً شکسته می‌شود چون توسعه‌دهنده با کپی `fa.php` این ۵۶ کلید را نخواهد دید.
**اقدام:** هر ۵۶ کلید را به `fa.php` اضافه کنید؛ نگاشت‌های `helpers.php` را فقط به‌عنوان fallback نهایی نگه دارید.

**۲. رشته‌های فارسی hardcode شده را استخراج کنید.**

| فایل | خط | محتوا |
|---|---|---|
| `includes/needs-attention.php` | ۱۰–۱۲ | برچسب سطوح: بحرانی / هشدار / اطلاع‌رسانی |
| `includes/import.php` | ۵۸–۶۱ | برچسب نوع موجودیت: ایمیل‌ها / سرویس‌ها / … |
| `db.php` | ۲۷ | پیام خطای اتصال دیتابیس |
| `install.php` | کل فایل | ۱۹ رشته + `dir="rtl"` ثابت |

**۳. جداکننده فهرست را locale-aware کنید.**
در `modules/import/mapping.php:42` و `modules/import/preview.php:95` از ویرگول فارسی `'، '` به‌صورت ثابت استفاده شده است. انگلیسی به `', '` نیاز دارد.
**اقدام:** کلید `common.list_separator` بسازید و در هر دو نقطه از `t('common.list_separator')` استفاده کنید.

**۴. برای LTR یک CSS جداگانه اضافه کنید.**
هم‌اکنون فقط `bootstrap.rtl.min.css` بسته‌بندی شده و در `includes/header.php`, `login.php`, `install.php` بدون شرط بارگذاری می‌شود. Bootstrap 5 از logical properties استفاده می‌کند، پس چیدمان با `dir="ltr"` درست کار می‌کند، اما بهینه نیست.
**اقدام:** `bootstrap.min.css` (نسخه LTR) را کنار آن قرار دهید و انتخاب را شرطی کنید:
```php
$bs = currentTextDirection() === 'rtl' ? 'bootstrap.rtl.min.css' : 'bootstrap.min.css';
```

**۵. `SUPPORTED_LANGUAGES` را از روی پوشه `lang/` بسازید.**
هم‌اکنون یک `const` ثابت در `includes/lang.php` است، پس افزودن زبان نیاز به ویرایش کد دارد.
**اقدام:** با `glob(APP_ROOT . '/lang/*.php')` زبان‌ها را کشف کنید و نام نمایشی را از کلید `app.native_name` داخل هر فایل بخوانید.

### اولویت متوسط — تجربه کاربری

**۶. زبان را در پروفایل کاربر ذخیره کنید.**
هم‌اکنون فقط در session است؛ با مرورگر جدید یا دستگاه دیگر به فارسی برمی‌گردد.
**اقدام:** ستون `users.preferred_language` اضافه کنید و در `setLanguage()` هم‌زمان با session بنویسید.

**۷. تقویم شمسی/هجری اضافه کنید.**
همه تاریخ‌ها میلادی و به شکل `Y-m-d` هستند. کاربر فارسی‌زبان انتظار تاریخ شمسی دارد.
**اقدام:** یک تابع `formatDate($iso)` در `helpers.php` بسازید که بر اساس `t('app.calendar')` خروجی را تبدیل کند. با `IntlDateFormatter` (اگر افزونه `intl` فعال باشد) یا یک تابع تبدیل جلالی خالص PHP به‌عنوان fallback.
**نکته حیاتی:** ذخیره‌سازی در دیتابیس **باید** میلادی ISO باقی بماند — فقط نمایش تبدیل شود.

**۸. منطقه زمانی را قابل تنظیم کنید.**
`config.php` مقدار `Asia/Tehran` را ثابت کرده است. برای کاربر عراقی `Asia/Baghdad` لازم است.
**اقدام:** به تنظیمات کاربر منتقل شود، با همان مقدار به‌عنوان پیش‌فرض.

**۹. ارقام محلی را در نظر بگیرید.**
اعداد همیشه با ارقام لاتین نمایش داده می‌شوند. برای فارسی می‌توان ارقام فارسی (۰۱۲۳) و برای عربی ارقام هندی-عربی (٠١٢٣) استفاده کرد.
**اقدام:** تابع `formatNumber()` مبتنی بر کلید `app.digits`. **هشدار:** هرگز روی مقادیر داخل `input` یا در کوئری اعمال نشود — فقط در خروجی نمایشی.

**۱۰. مرتب‌سازی الفبایی را اصلاح کنید.**
`ORDER BY` در SQLite از مقایسه باینری استفاده می‌کند، پس مرتب‌سازی الفبایی فارسی و عربی نادرست است (حروف «ی/ي» و «ک/ك» یکسان دیده نمی‌شوند).
**اقدام کوتاه‌مدت:** پیش از ذخیره، کاراکترهای عربی را به فارسی نرمال‌سازی کنید.
**اقدام بلندمدت:** برای فهرست‌های کوتاه، مرتب‌سازی را در PHP با `Collator` انجام دهید.

### اولویت پایین

**۱۱. ستون‌های CSV برای Import/Export را چندزبانه کنید.**
نگاشت ستون‌ها در `includes/import.php` فقط نام‌های انگلیسی را می‌شناسد. کاربری که فایل اکسل فارسی دارد باید دستی نگاشت کند.
**اقدام:** نام‌های مستعار فارسی و عربی را به جدول نگاشت اضافه کنید.

**۱۲. برای Export، BOM اضافه کنید.**
اکسل ویندوزی بدون BOM فایل UTF-8 فارسی را به‌درستی باز نمی‌کند. هنگام پیاده‌سازی Export حتماً `\xEF\xBB\xBF` در ابتدای فایل قرار دهید.

**۱۳. پشتیبانی از حالت جمع در `t()` اضافه کنید.**
هم‌اکنون `t()` فقط جایگزینی `:name` را پشتیبانی می‌کند. انگلیسی دو حالت جمع دارد و عربی شش حالت.
**اقدام:** یک تابع `tn($key, $count)` اضافه کنید یا پیام‌ها را طوری بنویسید که به جمع وابسته نباشند (مثلاً «تعداد: ۵»).

**۱۴. مستندات را به عربی ترجمه کنید** — `README.ar.md` و `docs/*.ar.md`.

## ۳. افزودن یک زبان جدید (مثلاً عربی)

پس از انجام موارد ۱ تا ۵ بالا:

۱. `cp lang/en.php lang/ar.php`
۲. مقادیر را ترجمه کنید و این سه کلید را تنظیم کنید:
```php
'app.direction'   => 'rtl',
'app.locale'      => 'ar',
'app.native_name' => 'العربية',
```
۳. مطمئن شوید تعداد کلیدها دقیقاً با `fa.php` یکسان است:
```bash
php -r "echo count(require 'lang/ar.php'), PHP_EOL;"
php -r "echo count(require 'lang/fa.php'), PHP_EOL;"
```
۴. فونت: Vazirmatn حروف عربی را پشتیبانی می‌کند اما برای متن عربی طراحی نشده است. برای کیفیت بهتر یک فونت عربی (مثلاً Noto Naskh Arabic) به `assets/fonts/` اضافه و به‌صورت شرطی بارگذاری کنید.
۵. تست کنید: هر صفحه، سوییچ زبان روی هر صفحه، فرم‌ها، ویزارد Import.

## ۴. قوانین ثابت برای هر ترجمه

1. **هیچ رشته قابل‌نمایشی نباید در PHP hardcode شود.** اگر کاربر آن را می‌بیند، باید `t()` داشته باشد.
2. **مقادیر enum در دیتابیس همیشه انگلیسی می‌مانند.** `'Active'` در DB ذخیره می‌شود، ترجمه فقط در لایه نمایش رخ می‌دهد. هرگز مقدار ترجمه‌شده را ذخیره نکنید.
3. **تاریخ‌ها همیشه به‌صورت ISO میلادی ذخیره می‌شوند.** تبدیل فقط برای نمایش.
4. **هر کلید جدید باید هم‌زمان به همه فایل‌های زبان اضافه شود** — یک کلید ناقص باعث نمایش خود کلید خام روی صفحه می‌شود.
5. **`t()` خروجی را escape نمی‌کند.** همیشه `e(t('key'))` بنویسید.
6. **هرگز جمله را از تکه‌های ترجمه‌شده نسازید** — ساختار جمله در زبان‌های مختلف متفاوت است. به‌جای آن از placeholder استفاده کنید:
```php
// ❌ غلط
t('found') . ' ' . $n . ' ' . t('accounts');
// ✅ درست
t('search.found_accounts', ['count' => $n]);   // "تعداد :count اکانت پیدا شد"
```

## ۵. اسکریپت بررسی تقارن کلیدها

این را قبل از هر commit اجرا کنید:

```bash
php -r '
$files = glob("lang/*.php");
$sets = [];
foreach ($files as $f) { $sets[basename($f, ".php")] = array_keys(require $f); }
$all = array_unique(array_merge(...array_values($sets)));
foreach ($sets as $lang => $keys) {
    $missing = array_diff($all, $keys);
    printf("%s: %d کلید، %d ناقص\n", $lang, count($keys), count($missing));
    foreach (array_slice($missing, 0, 20) as $k) { echo "   - $k\n"; }
}'
```
