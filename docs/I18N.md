# Internationalization Guide — Account Manager

🇮🇷 [فارسی](I18N.fa.md)

Current state: **Persian (default) + English**, ~590 translation keys, near-complete UI coverage.
This document explains how the system works, what remains, and exactly what to do to add a third language such as Arabic.

---

## 1. Current architecture

```
includes/lang.php   → the t() function, SUPPORTED_LANGUAGES, text direction
lang/fa.php         → Persian key => value array
lang/en.php         → English key => value array
set-language.php    → language switch + safe same-page redirect
```

The choice is stored in `$_SESSION['lang']`. `t()` has three fallback levels: current language → default language → the raw key itself.

**Key naming convention:** `<domain>.<name>` — e.g. `nav.emails`, `common.save`, `accounts.view_card_number`, `enum.Active`, `history.Account Created`.

**Text direction comes from the translation file, not from code:**
```php
'app.direction' => 'rtl',   // in fa.php
'app.direction' => 'ltr',   // in en.php
```
This is the right pattern and should be preserved.

## 2. Remaining i18n work

Ordered by priority. Items 1–5 should be done before adding a third language.

### High priority — structural debt

**1. Make the language files symmetric.**
`lang/en.php` has 34 `enum.*` keys and 22 `history.*` keys that **do not exist** in `lang/fa.php`. In Persian, `enumLabel()` falls back to hardcoded maps in `includes/helpers.php`. It works, but it is asymmetric — and it breaks immediately for a third language, because a developer copying `fa.php` will never see those 56 keys.
**Action:** add all 56 keys to `fa.php`; keep the `helpers.php` maps only as a last-resort fallback.

**2. Extract the remaining hardcoded Persian strings.**

| File | Line | Content |
|---|---|---|
| `includes/needs-attention.php` | 10–12 | Severity labels: Critical / Warning / Informational |
| `includes/import.php` | 58–61 | Entity type labels: Emails / Services / … |
| `db.php` | 27 | Database connection error message |
| `install.php` | whole file | 19 strings + hardcoded `dir="rtl"` |

**3. Make the list separator locale-aware.**
`modules/import/mapping.php:42` and `modules/import/preview.php:95` hardcode the Persian comma `'، '`. English needs `', '`.
**Action:** add a `common.list_separator` key and use `t('common.list_separator')` at both sites.

**4. Add a dedicated LTR stylesheet.**
Only `bootstrap.rtl.min.css` is bundled, and it is loaded unconditionally in `includes/header.php`, `login.php` and `install.php`. Bootstrap 5 uses logical properties, so layout does follow `dir="ltr"` correctly — but it isn't optimal.
**Action:** ship `bootstrap.min.css` alongside it and pick conditionally:
```php
$bs = currentTextDirection() === 'rtl' ? 'bootstrap.rtl.min.css' : 'bootstrap.min.css';
```

**5. Derive `SUPPORTED_LANGUAGES` from the `lang/` directory.**
It is currently a fixed `const` in `includes/lang.php`, so adding a language requires a code edit.
**Action:** discover languages with `glob(APP_ROOT . '/lang/*.php')` and read the display name from an `app.native_name` key inside each file.

### Medium priority — user experience

**6. Persist language in the user profile.**
It currently lives only in the session, so a new browser or device reverts to Persian.
**Action:** add a `users.preferred_language` column and write it in `setLanguage()` alongside the session.

**7. Add Jalali / Hijri calendar support.**
All dates are Gregorian `Y-m-d`. A Persian-speaking user expects Jalali dates.
**Action:** add a `formatDate($iso)` helper in `helpers.php` that converts based on an `app.calendar` key — via `IntlDateFormatter` where the `intl` extension is available, with a pure-PHP Jalali converter as fallback.
**Critical:** storage **must** stay Gregorian ISO — convert only for display.

**8. Make the timezone configurable.**
`config.php` hardcodes `Asia/Tehran`. An Iraqi user needs `Asia/Baghdad`.
**Action:** move it to user settings, keeping the current value as the default.

**9. Consider localized digits.**
Numbers always render as Latin digits. Persian could use Persian digits (۰۱۲۳) and Arabic the Arabic-Indic set (٠١٢٣).
**Action:** a `formatNumber()` helper driven by an `app.digits` key. **Warning:** never apply it to values inside `input` elements or in queries — display output only.

**10. Fix alphabetical sorting.**
SQLite's `ORDER BY` uses binary comparison, so Persian and Arabic alphabetical sorting is wrong (ی/ي and ک/ك don't compare as equal).
**Short term:** normalize Arabic characters to Persian before saving.
**Long term:** for short lists, sort in PHP with `Collator`.

### Low priority

**11. Localize CSV import/export column headers.**
The column map in `includes/import.php` only recognizes English names. A user with a Persian Excel file has to map every column by hand.
**Action:** add Persian and Arabic aliases to the mapping table.

**12. Add a BOM to exports.**
Windows Excel will not open a UTF-8 Persian file correctly without one. When implementing Export, prepend `\xEF\xBB\xBF`.

**13. Add plural support to `t()`.**
`t()` currently only substitutes `:name`. English has two plural forms; Arabic has six.
**Action:** add a `tn($key, $count)` helper, or write messages so they don't depend on plural agreement (e.g. "Count: 5").

**14. Translate the documentation into Arabic** — `README.ar.md` and `docs/*.ar.md`.

## 3. Adding a new language (e.g. Arabic)

After completing items 1–5 above:

1. `cp lang/en.php lang/ar.php`
2. Translate the values and set these three keys:
```php
'app.direction'   => 'rtl',
'app.locale'      => 'ar',
'app.native_name' => 'العربية',
```
3. Verify the key count matches `fa.php` exactly:
```bash
php -r "echo count(require 'lang/ar.php'), PHP_EOL;"
php -r "echo count(require 'lang/fa.php'), PHP_EOL;"
```
4. Font: Vazirmatn covers Arabic letterforms but was not designed for Arabic text. For better quality, add an Arabic face (e.g. Noto Naskh Arabic) to `assets/fonts/` and load it conditionally.
5. Test: every page, the language switcher on every page, all forms, the import wizard.

## 4. Standing rules for any translation

1. **No user-visible string is ever hardcoded in PHP.** If the user can see it, it needs `t()`.
2. **Enum values stay English in the database.** `'Active'` is what gets stored; translation happens only at the display layer. Never store a translated value.
3. **Dates are always stored as Gregorian ISO.** Convert for display only.
4. **Every new key goes into every language file at once** — a missing key renders the raw key on screen.
5. **`t()` does not escape.** Always write `e(t('key'))`.
6. **Never build a sentence from translated fragments** — word order differs between languages. Use placeholders instead:
```php
// ❌ wrong
t('found') . ' ' . $n . ' ' . t('accounts');
// ✅ right
t('search.found_accounts', ['count' => $n]);   // "Found :count accounts"
```

## 5. Key-symmetry check script

Run this before every commit:

```bash
php -r '
$files = glob("lang/*.php");
$sets = [];
foreach ($files as $f) { $sets[basename($f, ".php")] = array_keys(require $f); }
$all = array_unique(array_merge(...array_values($sets)));
foreach ($sets as $lang => $keys) {
    $missing = array_diff($all, $keys);
    printf("%s: %d keys, %d missing\n", $lang, count($keys), count($missing));
    foreach (array_slice($missing, 0, 20) as $k) { echo "   - $k\n"; }
}'
```
